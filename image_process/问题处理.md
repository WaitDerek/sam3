# image_process 问题处理

本文档记录 `image_process` 常见运行问题、排查命令和处理办法。命令默认在 `sam3` 仓库根目录执行。

## 1. 目录或参数写错

常见现象：

```text
FileNotFoundError
no images found
输出写到了 image_process/out 之外的目录
run_material_segmentation.py 能启动但没有处理预期图片
mask、metadata、overlays、pcd 数量对不上
```

处理办法：

```text
1. 命令统一在 sam3 仓库根目录执行。
2. Linux/WSL 使用 / 路径；Windows PowerShell 使用 \ 路径。
3. 路径中有中文、空格或括号时必须加引号。
4. run_material_segmentation.py 的 JSON 配置路径相对 image_process 目录解析。
5. detect_material_bgr.py 显式传入 --input-dir 和 --output-dir 时，优先使用仓库内相对路径。
6. 正式交付前用 align_dataset.py 对齐 bgr、depth、masks、metadata、overlays、pcd。
```

Linux/WSL 检查：

```bash
pwd
ls image_process
ls dataset/merged_ktxfk/bgr | head
python image_process/run_material_segmentation.py \
  --label 空调新风口 \
  --write-params-only
```

Windows PowerShell 检查：

```powershell
Get-Location
Get-ChildItem image_process
Get-ChildItem dataset\merged_ktxfk\bgr | Select-Object -First 5
python image_process\run_material_segmentation.py `
  --label 空调新风口 `
  --write-params-only
```

如果已经误删或人工删除了一部分 `overlays`，以 `overlays` 为基准对齐：

Linux/WSL：

```bash
python image_process/align_dataset.py \
  dataset/merged_cb \
  --base overlays \
  --targets bgr depth masks metadata pcd \
  --apply
```

Windows PowerShell：

```powershell
python image_process\align_dataset.py `
  dataset\merged_cb `
  --base overlays `
  --targets bgr depth masks metadata pcd `
  --apply
```

## 2. 分割结果不正确

常见现象：

```text
漏检：明显目标没有 mask。
误检：料箱、泡棉、桌面、阴影或红色框被纳入。
目标数错误：两个目标只识别一个，或粘连成一个。
边缘不完整：mask 没有完全包围目标。
空洞：中间镂空物料需要整体 mask，但内部被挖空。
```

处理办法：

```text
1. 先对单张或少量图片补跑，不要直接全量覆盖。
2. 漏检时加强目标形态描述，适当降低 --min-score。
3. 误检时在 prompt 中加入 object only、not crate、not foam、not table，并收紧 --max-area-frac。
4. 两个目标粘连时先试 --split-components，再试 --kmeans-split-instances。
5. 边缘不平滑时用 --mask-close-kernel；内部空洞用 --fill-holes。
6. 白色泡棉误入时加 --exclude-bright-pixels。
7. 仍不确定的图片移动到人工复检目录，用 Label Studio 标注后转换回 masks。
```

示例：

```bash
python image_process/detect_material_bgr.py \
  --input-dir dataset/merged_qtxzj/bgr \
  --output-dir out/merged_qtxzj_recheck \
  --label 背门驱动机构撑杆上球头销支架（左） \
  --image-stem 20260522_174451__000152 \
  --text-prompt "small black ball stud bracket in blue foam bin cell, object only, not blue crate grid" \
  --max-instances 2 \
  --min-score 0.25 \
  --split-components \
  --mask-close-kernel 3
```

```powershell
python image_process\detect_material_bgr.py `
  --input-dir dataset\merged_qtxzj\bgr `
  --output-dir out\merged_qtxzj_recheck `
  --label 背门驱动机构撑杆上球头销支架（左） `
  --image-stem 20260522_174451__000152 `
  --text-prompt "small black ball stud bracket in blue foam bin cell, object only, not blue crate grid" `
  --max-instances 2 `
  --min-score 0.25 `
  --split-components `
  --mask-close-kernel 3
```

## 3. CUDA 不可用或装成 CPU Torch

常见现象：

```text
Torch not compiled with CUDA enabled
torch.cuda.is_available() 输出 False
CUDA is not available. Disabling autocast.
运行速度明显很慢，GPU 占用为 0
```

检查：

Linux/WSL：

```bash
nvidia-smi || /usr/lib/wsl/lib/nvidia-smi
python \
  -c "import torch; print(torch.__version__); print(torch.version.cuda); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'no cuda')"
```

Windows PowerShell：

```powershell
nvidia-smi
python `
  -c "import torch; print(torch.__version__); print(torch.version.cuda); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'no cuda')"
```

处理办法：

```text
1. 先更新 NVIDIA 显卡驱动，确保 nvidia-smi 正常。
2. 确认当前终端激活的是 sam 环境，不是 base 或系统 Python。
3. 如果 torch 版本没有 +cuXXX，说明是 CPU 版，需要重装 GPU 版 torch。
4. RTX 50 系列建议使用 CUDA 12.8 对应的 PyTorch 包。
5. WSL 下优先更新 Windows NVIDIA 驱动，不要在 WSL 内安装 Linux 显卡驱动。
```

## 4. GPU 降频、速度忽快忽慢

常见现象：

```text
GPU 利用率突然下降。
nvidia-smi 中功耗、温度或显存接近限制。
笔记本未接电源时速度明显降低。
长时间批量分割后速度越来越慢。
```

检查：

Linux/WSL：

```bash
watch -n 1 nvidia-smi
nvidia-smi \
  -q \
  -d CLOCK,POWER,TEMPERATURE,PERFORMANCE
```

Windows PowerShell：

```powershell
nvidia-smi -l 1
nvidia-smi `
  -q `
  -d CLOCK,POWER,TEMPERATURE,PERFORMANCE
```

处理办法：

```text
1. 笔记本接电源，Windows 电源模式改为最佳性能。
2. NVIDIA 控制面板中把电源管理模式改为 Prefer maximum performance。
3. 关闭占用 GPU 的浏览器、训练程序、可视化工具和游戏。
4. 检查温度；如果温度过高，暂停任务并改善散热。
5. 显存接近满载时，降低输入分辨率、减少并发任务或分批处理。
6. WSL 长时间任务异常变慢时，保存结果后执行 wsl --shutdown 再重开终端。
```

## 5. Windows 安全策略拦截 DLL

常见现象：

```text
DLL load failed while importing _ssl
DLL load failed while importing _regex
应用程序控制策略已阻止此文件
```

处理办法：

```text
1. 请管理员放行 Miniconda 安装目录和 conda 环境目录。
2. 或把 Miniconda 安装到管理员允许的位置，例如 C:\ProgramData\miniconda3。
3. 不要把同一个环境直接从 Linux/WSL 复制到 Windows 使用；需要分别创建或使用 Windows 打包环境。
4. 放行后重新打开 PowerShell，并重新激活环境。
```

## 6. 依赖冲突

常见现象：

```text
ResolutionImpossible
opencv-python depends on numpy>=2
sam3 depends on numpy<2
ModuleNotFoundError: No module named 'torch'
ModuleNotFoundError: No module named 'triton'
```

处理办法：

```text
1. 使用 image_process/envs/sam.yml 创建环境。
2. SAM3 环境保持 numpy>=1.26,<2。
3. OpenCV 使用 opencv-python>=4.10,<4.12，避免拉取要求 numpy>=2 的新版本。
4. Windows 上缺少 triton 时，优先使用仓库内兼容版本；不要单独混装来源不明的 triton。
5. 修改依赖后执行 python -m pip check。
```

命令：

```bash
conda env update \
  -n sam \
  -f image_process/envs/sam.yml \
  --prune
python \
  -m pip install \
  -e ".[image_process,image_process_sam,label_studio]"
python \
  -m pip check
```

```powershell
conda env update `
  -n sam `
  -f image_process\envs\sam.yml `
  --prune
python `
  -m pip install `
  -e ".[image_process,image_process_sam,label_studio]"
python `
  -m pip check
```

## 7. 图形界面打不开

常见现象：

```text
qt.qpa.xcb: could not connect to display
Could not load the Qt platform plugin "xcb"
rviz2、realsense-viewer、open3d 可视化窗口打不开
```

处理办法：

```text
1. 如果在 WSL 中运行，先确认 echo $DISPLAY 有输出。
2. Windows 11 WSLg 异常时执行 wsl --update 和 wsl --shutdown。
3. SSH 远程机器需要使用 ssh -X 或 ssh -Y，并在本机安装 X Server。
4. 无窗口环境下用 visualize_pcd.py 的 --no-window 和 --screenshot。
```

Linux/WSL 离屏查看 PCD：

```bash
python image_process/visualize_pcd.py \
  dataset/merged_ktxfk/pcd/20260527_145449__000248.pcd \
  --no-window \
  --screenshot out/check_ktxfk.png
```
