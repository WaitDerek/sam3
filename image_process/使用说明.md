# SAM 3.1 物料分割使用说明

本仓库用于用 SAM 3.1 对 `image_process/dataset/` 或整理后的数据目录中的物料图片进行分割检测，并可基于检测出的 mask 与 depth 生成目标点云。

本分支以官方 `sam3.1` 发布分支为基础，当前项目的检测逻辑、检测参数和项目说明统一放在 `image_process/` 中。

## 目录说明

```text
image_process/dataset/
  test/                                 # 保留的一份示例输入
  <物料目录>/bgr/                       # 待检测 RGB 图
  <物料目录>/depth/                     # 与 RGB 对应的深度图

image_process/out/
  <结果目录>/                           # 临时检测输出；确认归档后可清理

image_process/changan/
  <物料名>_<数量>/                      # 已确认完整的正式数据归档；不提交 Git
    bgr/
    depth/
    masks/
    metadata/
    overlays/
    pcd/

image_process/configs/
  object_segmentation_params.json        # 物料总索引
  materials/<物料名>/*.json               # 按物料保存的检测参数
  material_detection_registry.json        # 修复历史和复现备案

image_process/out/<结果目录>/
  overlays/                              # 可视化结果，*_det.jpg
  masks/                                 # 二值 mask，*_mask.png
  metadata/                              # 检测元数据，*.json

<归档数据集>/
  bgr/                                   # RGB 图，<stem>.png
  depth/                                 # 深度图，<stem>.png
  masks/                                 # 检测 mask，<stem>_mask.png
  pcd/                                   # 点云输出，<stem>.pcd
```

模型权重 `sam3.1_multiplex.pt` 放在仓库根目录本地使用，不提交到 Git。

后续新增原始输入统一放到 `image_process/dataset/`，不要再使用根目录 `data/` 或 `image_process/data/`。检测与试验输出统一写入 `image_process/out/`；当确认一类物料全部结果正确后，再整理到 `image_process/changan/<物料名>_<数量>/`。

## Label 规则

检测 label 使用纯物料名称，只保留物料名本身。

正确：

```bash
python image_process/run_material_segmentation.py --label 副雨刮器
```

## 参数文件

`image_process/configs/object_segmentation_params.json` 是总索引。它记录每种物料的输入目录、输出目录、参数快照路径，以及要加载哪些参数文件。

示例：

```json
{
  "label": "副雨刮器",
  "input_dir": "image_process/dataset/副雨刮器总成/bgr",
  "output_dir": "image_process/out/passenger_wiper",
  "parameter_dir": "image_process/configs/materials/副雨刮器",
  "parameter_files": [
    "image_process/configs/materials/副雨刮器/table_view.json",
    "image_process/configs/materials/副雨刮器/repair_profiles.json"
  ]
}
```

`image_process/configs/materials/<物料名>/*.json` 是真正控制检测行为的参数文件。稳定场景参数通常单独保存，例如：

```text
image_process/configs/materials/副雨刮器/table_view.json
image_process/configs/materials/保险杠/bin_view.json
```

少量图片、单张图片或补充检测过程中形成的修复参数，应合并到对应物料的：

```text
image_process/configs/materials/<物料名>/repair_profiles.json
```

`repair_profiles.json` 使用 `profiles` 数组保存多个修复 profile。每个 profile 可以有自己的 `stems`、阈值和 prompt。

```json
{
  "name": "repair_profiles",
  "scene": "repair_bundle",
  "profiles": [
    {
      "name": "example_repair",
      "scene": "manual_repair",
      "stems": [
        "20260521_000000__000001"
      ],
      "threshold_overrides": {
        "min_score": 0.25,
        "min_area_frac": 0.0003,
        "max_area_frac": 0.05,
        "max_instances": 2
      },
      "prompts": [
        "target object prompt"
      ]
    }
  ]
}
```

常见字段：

- `sequence_prefixes`：按采集前缀批量匹配图片。
- `stems`：指定一组图片 stem，适合少量补检或清理。
- `threshold_overrides`：覆盖物料默认阈值。
- `prompts`：该场景或修复 profile 使用的文本提示。
- `scene`：场景类型，例如 `single_object`、`contact`、`container`、`manual_repair`、`repair_bundle`。

不要再为补检过程新增 `.txt` 时间戳清单。少量图片范围直接写入 JSON 的 `stems` 字段。

## 检测命令

按配置跑某个物料：

```bash
python image_process/run_material_segmentation.py --label 三角牌
python image_process/run_material_segmentation.py --label 保险杠
```

跑全部配置物料：

```bash
python image_process/run_material_segmentation.py
```

清空配置中的输出目录后重新检测：

```bash
python image_process/run_material_segmentation.py --label 保险杠 --clean
```

只生成参数快照，不跑检测：

```bash
python image_process/run_material_segmentation.py --write-params-only
```

配置检测输出由 `image_process/configs/object_segmentation_params.json` 中每个物料的 `output_dir` 决定，通常为：

```text
image_process/out/<结果目录>/masks
image_process/out/<结果目录>/overlays
image_process/out/<结果目录>/metadata
```

## 指定图片临时检测

如果只想快速跑一张或几张图片，不改总索引，可以直接调用底层脚本。`--image-stem` 可重复传入，每个 stem 会在 `--input-dir` 下解析为 `<stem>.png`。

```bash
python image_process/detect_material_bgr.py \
  --input-dir image_process/dataset/<物料目录>/bgr \
  --output-dir image_process/out/test_single \
  --label 副雨刮器 \
  --image-stem 20260521_000000__000001 \
  --min-score 0.25 \
  --min-area-frac 0.0003 \
  --max-area-frac 0.05 \
  --max-bbox-fill-frac 0.97 \
  --iou-dedup 0.3 \
  --max-instances 2 \
  --score-threshold-detection 0.05 \
  --new-det-thresh 0.1 \
  --text-prompt "single windshield wiper blade only" \
  --text-prompt "black curved rubber wiper blade only"
```

也可以直接指定单张图片路径：

```bash
python image_process/detect_material_bgr.py \
  --image image_process/dataset/<物料目录>/bgr/<图片文件>.png \
  --output-dir image_process/out/test_single \
  --label 副雨刮器 \
  --text-prompt "black windshield wiper blade"
```

## 点云生成

完成检测并整理成标准目录后，可以用 mask、depth 和 bgr 生成目标点云。

标准输入目录：

```text
<dataset>/
  bgr/
  depth/
  masks/
```

默认输出：

```text
<dataset>/pcd/<stem>.pcd
```

生成整个数据集：

```bash
python image_process/mask_depth_to_pcd.py --dataset-dir "image_process/changan/三角警告牌"
```

生成单张：

```bash
python image_process/mask_depth_to_pcd.py \
  --dataset-dir "image_process/changan/三角警告牌" \
  --frame 20260521_105214__000000
```

覆盖已有 `.pcd`：

```bash
python image_process/mask_depth_to_pcd.py \
  --dataset-dir "image_process/changan/三角警告牌" \
  --overwrite
```

非标准目录可以显式指定：

```bash
python image_process/mask_depth_to_pcd.py \
  --bgr-dir path/to/bgr \
  --depth-dir path/to/depth \
  --mask-dir path/to/masks \
  --output-dir path/to/pcd
```

查看点云：

```bash
python image_process/visualize_pcd.py "image_process/changan/三角警告牌/pcd/20260521_105214__000000.pcd"
```

查询图像中某个像素点的三维坐标：

```bash
python image_process/pixel_to_xyz.py \
  --dataset-dir "image_process/changan/三角警告牌" \
  --frame 20260521_105214__000000 \
  --pixel 640,360 \
  --check-mask
```

如果该像素没有有效深度，可以加一个小范围搜索：

```bash
python image_process/pixel_to_xyz.py \
  --dataset-dir "image_process/changan/三角警告牌" \
  --frame 20260521_105214__000000 \
  --pixel 640,360 \
  --search-radius 5
```

## 维护原则

- 新增稳定场景时，优先新增 `image_process/configs/materials/<物料名>/<场景>.json`。
- 单张或少量图片的补检、误检清理，优先追加到 `image_process/configs/materials/<物料名>/repair_profiles.json`。
- 不要为了局部问题编号改坏已有稳定场景。
- 不要提交补检过程中的 `.txt` 时间戳清单。
- `image_process/dataset/`、`image_process/out/` 和 `image_process/changan/` 是本地数据与输出，不进入 Git。
