# SAM 3.1 物料分割使用说明

*新增内容自368行开始*
本仓库用于用 SAM 3.1 对 `dataset/` 或整理后的数据目录中的物料图片进行分割检测，并可基于检测出的 mask 与 depth 生成目标点云。

本分支以官方 `sam3.1` 发布分支为基础，当前项目的检测逻辑、检测参数和项目说明统一放在当前 `image_process` 工作目录中。

环境安装和依赖说明见 `环境配置说明.md`。

## 参数文件
`configs/object_segmentation_params.json` 是总索引。它记录每种物料的输入目录、输出目录、参数快照路径，以及要加载哪些参数文件。
示例：

```json
{
  "label": "副雨刮器",
  "input_dir": "dataset/副雨刮器总成/bgr",
  "output_dir": "out/passenger_wiper",
  "parameter_dir": "configs/materials/副雨刮器",
  "parameter_files": [
    "configs/materials/副雨刮器/table_view.json",
    "configs/materials/副雨刮器/repair_profiles.json"
  ]
}
```

`configs/materials/<物料名>/*.json` 是真正控制检测行为的参数文件。稳定场景参数通常单独保存，例如：

```text
configs/materials/副雨刮器/table_view.json
configs/materials/保险杠/bin_view.json
```

少量图片、单张图片或补充检测过程中形成的修复参数，应合并到对应物料的：

```text
configs/materials/<物料名>/repair_profiles.json
```

`repair_profiles.json` 使用 `profiles` 数组保存多个修复 profile。每个 profile 可以有自己的 `stems`、阈值和 prompt。

```json
{
  "name": "repair_profiles",
  "scene": "repair_bundle",
  "profiles": [
    {
      "name": "example_repair",
      "scene": "manual_repair",
      "stems": [
        "20260521_000000__000001"
      ],
      "threshold_overrides": {
        "min_score": 0.25,
        "min_area_frac": 0.0003,
        "max_area_frac": 0.05,
        "max_instances": 2
      },
      "prompts": [
        "target object prompt"
      ]
    }
  ]
}
```

常见字段：

- `sequence_prefixes`：按采集前缀批量匹配图片。
- `stems`：指定一组图片 stem，适合少量补检或清理。
- `threshold_overrides`：覆盖物料默认阈值。
- `prompts`：该场景或修复 profile 使用的文本提示。
- `scene`：场景类型，例如 `single_object`、`contact`、`container`、`manual_repair`、`repair_bundle`。

不要再为补检过程新增 `.txt` 时间戳清单。少量图片范围直接写入 JSON 的 `stems` 字段。

## Raw/RGB-D 数据准备

对于厂商导出的单帧原始数据，常见输入包括：

```text
<timestamp>_W1920_H1456_Depth16.raw      # 16-bit 深度 raw
<timestamp>_W4000_H3000.jpg              # 彩色图
<timestamp>_W4000_H3000_RGB8Planar.raw   # 无压缩 RGB planar raw，可选
Sensor_xxx.mfa                           # 相机内参/标定文件
```

### 1. Depth16 raw 转 depth PNG

`raw_depth_to_png.py` 会从文件名读取深度分辨率，并输出 16-bit PNG。若传入 `.mfa`，会同时写出深度相机内参。

```bash
python raw_depth_to_png.py \
  dataset/demo/20260604095608625_W1920_H1456_Depth16.raw \
  --output-dir dataset/demo_prepared/depth \
  --mfa dataset/demo/Sensor_00DA2021501.mfa \
  --write-intrinsics dataset/demo_prepared/intrinsic.json
```

输出：

```text
dataset/demo_prepared/depth/<timestamp>.png
dataset/demo_prepared/intrinsic.json
```

### 2. 直接把 depth 拉伸到 RGB 分辨率

如果希望保留原始彩色图分辨率，例如 `4000x3000`，使用 `resize_depth_to_rgb.py`。这个脚本不使用 depth/RGB 外参，也不做 z-buffer，只把 depth 直接 resize 到 RGB 分辨率，并写入 RGB 相机内参。

```bash
python resize_depth_to_rgb.py \
  --color dataset/demo/20260604095608625_W4000_H3000.jpg \
  --depth dataset/demo_prepared/depth/20260604095608625.png \
  --output-dir dataset/demo_rgb_resized_depth
```

默认行为：

- `--stem` 会从彩色图文件名自动推断，例如 `20260604095608625_W4000_H3000.jpg` 会输出为 `20260604095608625.png`。
- `--depth-scale` 默认是 `10000`。
- 默认会覆盖已有输出；如果希望已有输出时报错，加 `--no-overwrite`。
- `--mfa` 可省略，脚本会在输入/输出附近自动查找 `Sensor_*.mfa`。

输出标准数据集：

```text
dataset/demo_rgb_resized_depth/
  bgr/<timestamp>.png       # 4000x3000 彩色图
  depth/<timestamp>.png     # 4000x3000，直接 resize 后的 depth
  intrinsic.json            # RGB 相机内参 + depth_scale
```

`--color` 也可以直接使用 `*_RGB8Planar.raw`，脚本会按 `RRR...GGG...BBB...` 的 planar RGB8 格式读取。已有 `.jpg` 时可以先用 `.jpg`；需要无压缩彩色图时再改用 raw。

### 3. Depth scale 注意事项

这批 demo 的 `Depth16.raw` 数值范围对应 0.1mm 单位，因此点云脚本需要使用：

```bash
--depth-scale 10000
```

不要使用旧 RealSense 数据常用的默认 `--depth-scale 1000`，否则深度会被解释成 10 倍距离。

## 检测命令

按配置跑某个物料：

```bash
python run_material_segmentation.py --label 三角牌
python run_material_segmentation.py --label 保险杠
```

跑全部配置物料：

```bash
python run_material_segmentation.py
```

只重跑改动过的某个 profile（增量，不会重跑整个物料的其它 profile）：

```bash
# 例如只改了多箱 profile 的参数，就只重跑它，单箱/修复 profile 的结果原样保留
python run_material_segmentation.py --label box1 --profile box1_multi_whole_crate
```

`--profile` 可重复传入，按 profile 名称过滤（名称见各物料 JSON 里的 `name` 字段）。检测会直接覆盖对应帧的输出，无需先清空。

断点续跑（跳过已生成结果的帧）：

```bash
python run_material_segmentation.py --label box1 --skip-existing
```

> 注意：`--skip-existing` 会跳过已存在的输出，**改了参数后不要加它**（否则改动帧被跳过）；它只用于续跑被中断的任务。需要彻底清空某个输出目录时，直接 `rm -rf out/<结果目录>`（已移除 `--clean`，避免动辄全量重跑）。

只生成参数快照，不跑检测：

```bash
python run_material_segmentation.py --write-params-only
```

配置检测输出由 `configs/object_segmentation_params.json` 中每个物料的 `output_dir` 决定，通常为：

```text
out/<结果目录>/masks
out/<结果目录>/overlays
out/<结果目录>/metadata
```

## 指定图片临时检测

如果只想快速跑一张或几张图片，不改总索引，可以直接调用底层脚本。`--image-stem` 可重复传入，每个 stem 会在 `--input-dir` 下解析为 `<stem>.png`。

```bash
python detect_material_bgr.py \
  --input-dir dataset/<物料目录>/bgr \
  --output-dir out/test_single \
  --label 副雨刮器 \
  --image-stem 20260521_000000__000001 \
  --min-score 0.25 \
  --min-area-frac 0.0003 \
  --max-area-frac 0.05 \
  --max-bbox-fill-frac 0.97 \
  --iou-dedup 0.3 \
  --max-instances 2 \
  --score-threshold-detection 0.05 \
  --new-det-thresh 0.1 \
  --text-prompt "single windshield wiper blade only" \
  --text-prompt "black curved rubber wiper blade only"
```

也可以直接指定单张图片路径：

```bash
python detect_material_bgr.py \
  --image dataset/<物料目录>/bgr/<图片文件>.png \
  --output-dir out/test_single \
  --label 副雨刮器 \
  --text-prompt "black windshield wiper blade"
```

## 点云生成

完成检测并整理成标准目录后，可以用 mask、depth 和 bgr 生成目标点云。

标准输入目录：

```text
<dataset>/
  bgr/
  depth/
  masks/
```

默认输出：

```text
<dataset>/pcd/<stem>.pcd
```

生成整个数据集：

```bash
python mask_depth_to_pcd.py --dataset-dir "changan/三角警告牌"
```

生成单张：

```bash
python mask_depth_to_pcd.py \
  --dataset-dir "changan/三角警告牌" \
  --frame 20260521_105214__000000
```

覆盖已有 `.pcd`：

```bash
python mask_depth_to_pcd.py \
  --dataset-dir "changan/三角警告牌" \
  --overwrite
```

非标准目录可以显式指定：

```bash
python mask_depth_to_pcd.py \
  --bgr-dir path/to/bgr \
  --depth-dir path/to/depth \
  --mask-dir path/to/masks \
  --output-dir path/to/pcd
```

如果还没有 mask，只想检查整张 RGB-D 的点云质量，可以用全场景点云脚本：

```bash
python bgr_depth_to_pcd.py \
  --dataset-dir dataset/demo_rgb_resized_depth \
  --depth-scale 10000 \
  --max-depth 5.0 \
  --overwrite
```

查看点云：

```bash
python visualize_pcd.py "changan/三角警告牌/pcd/20260521_105214__000000.pcd"
python visualize_pcd.py "dataset/demo_rgb_resized_depth/pcd/20260604095608625.pcd"
```

查询图像中某个像素点的三维坐标：

```bash
python pixel_to_xyz.py \
  --dataset-dir "changan/三角警告牌" \
  --frame 20260521_105214__000000 \
  --pixel 640,360 \
  --check-mask
```

如果该像素没有有效深度，可以加一个小范围搜索：

```bash
python pixel_to_xyz.py \
  --dataset-dir "changan/三角警告牌" \
  --frame 20260521_105214__000000 \
  --pixel 640,360 \
  --search-radius 5
```

## 维护原则

- 新增稳定场景时，优先新增 `configs/materials/<物料名>/<场景>.json`。
- 单张或少量图片的补检、误检清理，优先追加到 `configs/materials/<物料名>/repair_profiles.json`。
- 不要为了局部问题编号改坏已有稳定场景。
- 不要提交补检过程中的 `.txt` 时间戳清单。
- `dataset/`、`out/` 和 `changan/` 是本地数据与输出，不进入 Git。

## 补充：通用 RealSense 物料数据处理流程

# RealSense 物料数据处理说明

本文档说明 `image_process/` 中脚本的用途、推荐环境和完整处理流程。命令默认从项目根目录运行，脚本路径统一写成 `image_process/xxx.py`，数据路径使用项目内相对路径。

## 目标

该流程用于处理 RealSense 采集的 RGB-D 物料数据，覆盖：

1. 从 `.bag` 抽帧，生成 `bgr/` 和 `depth/`
2. 合并同类物料的多段采集数据
3. 对齐 RGB、深度、masks、metadata、overlay 和 PCD
4. 使用 SAM3 生成目标 masks、metadata 和 overlay
5. 对漏检、误检、粘连、边缘不完整等样本进行补跑或人工复核
6. 用 `bgr + depth + mask` 生成目标级 PCD

最终整理后的数据集目录建议保持：

```text
dataset_name/
  bgr/
  depth/
  masks/
  metadata/
  overlays/
  pcd/
```

文件命名规则：

```text
bgr/<stem>.png
depth/<stem>.png
masks/<stem>_mask.png
metadata/<stem>.json
overlays/<stem>_det.jpg
pcd/<stem>.pcd
```

SAM3 原始输出默认在 `sam3_segmentation/` 下：

```text
sam3_segmentation/
  masks/<stem>_mask.png
  metadata/<stem>.json
  overlays/<stem>_det.jpg
```

后续人工标注、PCD 生成和质量检查都以 `masks/`、`metadata/` 为标准目录名。

## 主流程

### 1. 抽帧

环境：`hangcha`


环境：`sam`

常用补充参数：

- `--image-stem <stem>`：只处理单张图
- `--image-list todo.txt`：按清单处理
- `--include-prefix 20260527_145449`：按文件名前缀处理
- `--skip-existing`：已有输出则跳过
- `--split-components`：把不相连连通域拆成多个目标
- `--kmeans-split-instances 2`：对粘连目标做近似拆分
- `--fill-holes`：填充目标内部空洞
- `--exclude-bright-pixels`：排除白色泡棉或亮色误检

## Prompt 编写规则

推荐顺序：

1. 目标本体：颜色、材质、形状、功能名称
2. 场景背景：桌面、蓝色泡沫格子、黑色分格箱、白色泡棉垫
3. 排除项：not crate、not foam、not tray wall、not reflection
4. 数量关系：有两个目标时写 `two visible ... separate each object`

示例：

```text
black rectangular hollow automotive HVAC fresh air inlet plastic part
black plastic fresh air inlet housing, object only, not foam or crate
small black bracket part inside blue foam grid compartment, not tray wall
two visible silver automotive logo emblems, separate each object
```

常见策略：

- 漏检：降低 `--min-score`，增加更具体 prompt，或按 `--image-list` 补跑。
- 误检：提高 `--min-score`，收紧 `--max-area-frac`，加入明确排除项。
- 粘连：先尝试 `--split-components`，再尝试 `--kmeans-split-instances 2`。
- 边缘破碎：使用 `--mask-close-kernel` 和 `--fill-holes`。
- 白色泡棉误入：使用 `--exclude-bright-pixels`。

## Label Studio 人工标注

适用场景：

- SAM3 漏检明显目标
- 两个目标贴得太近，被识别成一个整体
- 目标在料箱格子内，格子壁或泡棉被误包含
- mask 边缘不完整、不平滑或没有完全包住目标
- 遮挡严重，需要人工判断是否保留

### 环境配置

如果已有 `label_studio` 环境：


### 项目配置

新建项目时建议：

1. 模板选择 `Image Segmentation with Polygons` 或 Brush/Polygon 混合模板。
2. 标签名称使用中文物料名，例如 `车标`、`空调新风口总成`、`背门驱动机构撑杆上球头销支架（左）`。
3. 导入原图时使用 `bgr/`，不要导入 overlay 图。
4. 如果目标边界清晰，优先用 Polygon；如果目标边缘复杂，可以用 Brush。

一个简化的 Polygon 配置示例：

```xml
<View>
  <Image name="image" value="$image"/>
  <PolygonLabels name="label" toName="image">
    <Label value="车标"/>
    <Label value="空调新风口总成"/>
    <Label value="背门驱动机构撑杆上球头销支架（左）"/>
  </PolygonLabels>
</View>
```

标注规范：

- 一个真实物体对应一个独立 mask。
- 两个车标或两个箱内小件必须分成两个实例。
- 不要把料箱格子、白色泡棉、反光、桌面、阴影纳入目标。
- 能完整看见的目标尽量沿真实边缘标满。
- 遮挡超过约 40%、边界无法判断、两个目标严重重叠无法可靠拆分时，放入人工复核目录。
- 对中空但需要作为整体建模的物体，可按业务要求填充内部孔洞。

导出与回填：

1. 导出 `Label Studio JSON` 或 `COCO JSON`。
2. 用转换脚本生成 `masks/`、`metadata/` 和 `overlays/`。
3. 再用 `mask_depth_to_pcd.py` 根据人工 mask 重新生成 `pcd/`。
4. 将 Label Studio 原始导出归档到 `labelstudio_exports/`，便于追溯。

Label Studio JSON 转换：

```bash
conda activate label_studio
python image_process/labelstudio_json_to_masks.py \
  --json labelstudio_exports/cb_tasks.json \
  --dataset-dir 车标_1852 \
  --label 车标 \
  --overwrite
```

COCO JSON 转换：

```bash
python image_process/labelstudio_json_to_masks.py \
  --json labelstudio_exports/cb_coco.json \
  --dataset-dir 车标_1852 \
  --label 车标 \
  --overwrite
```

转换输出：

```text
车标_1852/
  masks/<stem>_mask.png
  metadata/<stem>.json
  overlays/<stem>_det.jpg
```

`metadata/<stem>.json` 中会包含 `detections`、面积、bbox 和 `prompt_suggestions`。这些信息可用于后续补写 SAM3 prompt 或检查人工标注类别是否一致。

## 质量检查

交付前至少检查：

- `bgr/` 与 `depth/` 是否一一对应
- `masks/` 是否完整包住目标
- `overlays/` 是否存在明显误检、漏检、粘连未拆分
- `metadata/` 中中文标签是否正确
- `pcd/` 是否和最终 mask 一一对应
- 人工删除或筛选后的样本是否已同步到其他目录

## 补充：pyproject 可选依赖

仓库根目录的 `pyproject.toml` 只保留功能型 optional dependencies，避免把 `hangcha`、`sam` 这类完整 conda 环境重复写进 TOML：

- `label_studio`：Label Studio 服务和 BrushLabels RLE 转换依赖

在已有 `sam` 环境中配置图像处理和 SAM 脚本依赖：

```bash
cd ~/workspace/sam3
```

```bash
python -m pip install "numpy>=1.26,<2" "opencv-python>=4.10,<4.12"
```

如果需要在 `sam` 环境中解析 Label Studio 的 BrushLabels 标注，再安装：

```bash
conda activate sam
cd ~/workspace/sam3
```

如果需要启动完整 Label Studio 服务，建议继续使用单独的 `label_studio` 环境，或显式安装：
